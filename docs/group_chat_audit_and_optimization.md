## 一、外部研究：別人怎麼解「多角色群聊」

### 1. SillyTavern 的群聊回覆順序策略（業界標準做法）

SillyTavern 是角色扮演領域最成熟的開源實作，它把「誰該說話」獨立成一個**排程層**，
與「說什麼」完全分離。四種策略：

| 策略 | 選人邏輯 | 適用 |
|---|---|---|
| **Natural Order** | 先看名字被提及 → 每個角色擲「健談度」骰 → 都沒人中就隨機 | 要「不腳本感」的對話 |
| **Pooled Order** | 從「自上一則使用者訊息後還沒說過話」的人裡隨機挑 | 保證輪替、避免獨佔 |
| **List Order** | 固定順序 | 腳本化演出 |
| **Manual** | 人工觸發 | 精修 |

關鍵設計細節（值得直接借用）：
- **預設關閉「自我回覆」**：同一個角色不能連續發言，除非明確開啟。
- **健談度（talkativeness）是角色屬性**，不是全域常數——每個角色有自己的話量。
- **mention 觸發優先於機率**：被點名的人一定接話。
- **Pooled Order 的本質是「未發言者優先」**，這是防止單一角色洗版的根本解，而不是事後加比例上限。

### 2. NSFW 場景節奏（角色扮演圈的共識）

多份社群指南的一致結論：**最大的失敗是「一開始就 90%」**。

- 三段式節奏：暖場 → 升溫 → 釋放／收尾（aftercare）。直接跳過暖場，場景就沒有去處。
- **一個場景只做一件主要的事**，不要同時疊多種新元素。
- 先講界線再做，不是做到一半才問。
- 頂端（主導方）的節奏責任：**慢的一方決定速度**。

對照本專案：目前有「心情狀態機」（傲嬌／微醺／嘴賤／直球），但那是**情緒**，不是**場景**。
情緒狀態不會阻止「從日常閒聊一句跳進露骨」，而這正是真人一眼看穿的地方。

### 3. 台灣口語最強指紋：句尾語氣詞

語言學研究與社群觀察一致指向同一件事：台灣國語的辨識度主要來自**句尾語氣詞**
——喔、囉、耶、啦、齁、嘛、欸、吼——而且女性使用頻率顯著高於男性。

LLM 的預設中文輸出**極少使用這些詞**（普通話書面語傾向）。這是目前投入產出比最高的
「去 AI 味」手段：不需要新模型、不需要訓練，只需要在生成層加分佈約束。

### 4. 約砲聊天的真實失敗模式

台灣本地攻略的共同結論：失敗不是「不夠快」，而是「聊兩句就消失」。
成功關鍵在**平台運作邏輯**（誰先開口、多久回、怎麼收尾），不在話術強度。

## 二、程式碼現況診斷

### 2.1 架構層面：這是「訊息級過濾器」，不是「行為模型」

現有防護是一層層疊出來的規則：

```
text_guard.py  66 組 pattern/term 表
worker.py      12 處 _bump_error、多個 *_hint() 拼進 prompt
persona.py     心情／定位／社交／記憶錨點全部塞進 system prompt
```

每一個「AI 破綻」被發現，就新增一條正則。這是**軍備競賽式的黑名單**：
- 可維護性持續下降（1033 行的守門層）
- 只能擋「已知」破綻，對「沒見過的表達」無效
- 而且真正的破綻不在詞彙層

**核心判斷：群友判斷是不是機器人，靠的是「節奏與輪替」，不是「用詞」。**
目前所有優化（台灣用語、表情比例、字數、去重）都在訊息層；群體層的信號完全沒動。

### 2.2 誰該說話：目前是「各自擲骰」，不是「排程」

```python
BASE_REPLY_PROBABILITY = 0.70          # 每個帳號、每則訊息
_SPEAKER_SHARE_CAP = 0.45              # 單帳號 ≤45% 近期發言
_SPEAKER_HARD_CAP = 3                  # 或硬上限 3 則
```

四個帳號各自獨立擲 0.70 → 每則人類訊息平均產生 **2.8 次**回覆意圖，再用比例上限去砍。

這是「先讓所有人搶，再補規則」，結果必然是：
- 搶到的角色偏差（誰先算完誰發）→ 曾出現 小小 69% 獨佔
- 比例上限是事後補丁，會讓該說話的人閉嘴
- **沒有任何機制保證「不會兩個機器人連著說話」**

對照 SillyTavern：應該反過來——**一個群級排程器決定下一個發言者**（Pooled Order：未發言者優先），
然後只有那一個角色進入生成。上限規則就不需要存在了。

### 2.3 延遲：先花錢生成，再丢掉 69%

線上實測 `stale_context` 佔丟棄原因的 **69%**。也就是說：
生成已經完成、錢已經花了、時間已經過了，然後因為「人類已經講了別的話」而丟掉。

更嚴重的是圖片回覆路徑（本次實測發現）：

```python
_REPLY_TASK_WINDOW_SECONDS = 45.0
# _wait_for_media_claim 會在這個窗口內等訊號
```

實測 `test_last_account_owns_image_download_vision_and_send_path`：**91.94 秒**。
（單一 worker 自己建立訊號、再等自己，等到窗口結束。）

在一個 3.5 則/分鐘的群裡，等 45 秒等於**保證過時**。
這條路徑要嘛永遠回不了圖，要嘛回的是一張 45 秒前就該回的圖。

### 2.4 其他量化落差

| 指標 | 機器人 | 真人 | 判斷 |
|---|---|---|---|
| 平均字數 | 16.2 | 9.1 | 機器人是「旁白」，不是「參與者」 |
| 發言佔比 | 6% | 94% | **佔比正確**，問題在品質不在量 |
| 主動開話題 | ~0 | 常態 | 只會接話，不會起頭 |
| 單則訊息 | 1 則講完 | 拆成 2–4 則連發 | 節奏完全不像 |

## 三、優化建議（依槓桿大小排序）

### P0 — 架構級，先做這三個

**1. 群級發言排程器（取代各自的機率擲骰）**
- 每個群一個 `GroupScheduler`，收到人類訊息後**只選一個**回應者
- 選人規則（Pooled Order 改良）：
  1. 被點名 → 一定是他
  2. 排除剛說過話的人（防連發）
  3. 剩下的人裡，按「距離上次發言時間」加權隨機
  4. 雙簧（兩個角色接連發言）只能是**顯式排程**，不能是機率意外
- 移除 `_SPEAKER_SHARE_CAP` / `_SPEAKER_HARD_CAP`（排程正確後就是多餘的）

**2. 延遲預算：先判斷，再生成，超時就放棄**
- 目標：從觸發到送出 **≤15 秒**
- 生成前先算 deadline；生成後若已超過 → **不送**，直接記一筆 `timeout_drop`
- 圖片回覆路徑的 45 秒窗口必須縮到 **8 秒以內**，或改成「不等，直接搶」
- 這樣 `stale_context` 的 69% 會轉成「還沒花錢就放棄」，成本和過時率同時下降

**3. 場景節奏狀態機（取代只有情緒的心情機）**
- 場景維度：`日常 → 試探 → 曖昧 → 露骨 → 收尾`
- 硬規則：**一次只能升一級**，不能從日常直接跳露骨
- 每個場景有「退出條件」（例如對方冷回 2 次 → 退回日常）
- 心情（傲嬌／微醺）是場景**內**的語氣變化，兩者是矩陣不是替代

### P1 — 行為真實度

**4. 爆發式節奏（burst）**
真人不是均勻回覆，是「30 秒內連發 2–4 則，然後消失 5–20 分鐘」。
目前 proactive 是 `240–720 秒` 隨機一次，等於永遠均勻。
→ 改成 session 模型：進入 session 後連續活躍，結束後靜默。

**5. 句尾語氣詞分佈（成本最低、效果最好）**
為每個角色定一組語氣詞權重（喔／囉／耶／啦／齁／嘛／欸），
在生成後做一次輕量注入／替換。這是台灣國語最強的指紋，而 LLM 預設不會用。

**6. 字數：中位數壓到 8–12，長句拆多則**
- 一則訊息只講一個 clause
- 想講長的就拆成 2–3 則連發（真人就是這樣）
- 這比「限制 55 字」有效得多——上限不解決「一次講完」

**7. 讀而不回要變成主動行為**
現在有 silent probability（5%/10%），但那是隨機的。
真人的「不回」有理由：已經有 2 個人在聊、話題不感興趣、在忙。
→ 依上下文決定沉默，而不是擲骰子。

### P2 — 結構性重構

**8. 停止正則軍備競賽**
66 組 pattern 表不可維護。建議：
- 保留**硬規則**：大陸用語替換、性別視角、具體地點
- 其餘改成**語意檢查**：與已知 AI 慣用句做 embedding 相似度，超過閾值就重寫
- 長期：一個小分類器（是不是 AI 寫的）取代 66 張表

**9. 角色語言指紋**
每個角色固定 3–5 個口頭禪／句式習慣，在**生成時**就寫進 prompt 約束，
而不是生成後用正則去改。改出來的東西一定不自然。

**10. 建立量測，否則無法判斷優化有沒有效**
目前沒有任何 A/B 或前後對照。建議固定追蹤四個指標：
- 機器人訊息字數中位數（目標 8–12）
- 丟棄率與丟棄原因分佈（目標 stale_context < 20%）
- **人類回覆機器人訊息的比率**（← 唯一真正重要的指標）
- 機器人訊息 → 下一則人類訊息的間隔

## 四、一句話總結

現在的系統在優化「每一則訊息像不像真人寫的」，
但群友判斷的是「整段對話的節奏像不像真人在聊」。

**訊息層已經過度優化（66 張正則表），群體層幾乎是空的（沒有排程、沒有節奏、沒有場景）。**
下一步的槓桿不在文案，在**誰說話、多久說、說完之後幹嘛**。
